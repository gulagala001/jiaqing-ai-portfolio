VoxelBench 把作品要求拆成检查点

我提出体素世界评测设想，希望把生成作品的使用体验放进同一套检查流程。AI 辅助实现了题面、录分工作台、固定权重计算、榜单与作品预览。

一个可操作的小题

求职展示页提取了原题 QC1.1 的检查点。三个检查点额度为 4、3、3 分，可以分别选择完成程度，再由原评分函数合成小题得分。

实际操作页面结果规则的作用
未选择全部检查点保持未评分未观察不自动记作零，也不冒充完整结果
依次选择满档、半档、零档4 + 1.5 + 0 = 5.5 分按既定检查点额度合成，避免临时调整尺度
撤回一个检查点到未观察恢复未评分有缺项时不输出完整小题分数
清空体验页回到初始状态体验仅在当前浏览器内生效，不覆盖原始成绩

PenEcho 连接白板与持续会话

应用场景是持续手写问答：输入留在白板上，回复以文字和公式出现，控制台保留会话与轮次记录。项目在 PenEcho 白板、pi Agent 运行时和 Syncthing 的基础上做桥接与应用改造。

本次运行使用真实白板与桥接程序；模型回复由本地服务预设，Syncthing 由模拟服务代替。验证目标是请求、板书显示和会话流程；不是模型识字或解题能力测试，也不是安卓真机同步验收。

操作实际观察完成范围
打开独立白板与控制台页面加载，桥接在线，会话列表出现求职副本的本地启动
输入文本并加入手写笔迹，触发解释文字与公式草稿出现在画布，可确认真实界面与桥接流程，回复内容为预设
在控制台新建会话出现新会话与成功提示真实会话操作；保存位于独立演示目录
模拟一次上游 500 错误控制台记录异常，随后重试得到预设回复仅覆盖这一次故障重试，不能代表所有异常

演示中遇到的实际问题

独立副本缺少图像编码依赖，默认 WebP 输入提示不可用。求职助手将演示配置改为程序支持的 PNG 格式后，请求成功。预设回复最初沿用了旧测试中的命令形状，未能渲染；对齐当前白板的坐标和公式字段后才出现截图中的草稿。两项均属于本次演示准备，不作为本人历史调试经历。
